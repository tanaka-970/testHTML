Profiler と DX12 Debug

対象：ブランチ sinotake / コミット 9eb9813

Profiler / 描画統計 は、1 フレームにかかった時間（CPU と GPU）、描いた三角形の数、処理ごとの時間の内訳などを表示するウィンドウです。F4 で表示・非表示を切り替えます。DX12 Debug は、DirectX 12 の描画の内部の状態を数字で見るウィンドウです。

こんなときに使う

  • ゲームが重い（FPS が低い）ときに、CPU と GPU のどちらが原因か、どの処理に時間がかかっているかを調べたいとき
  • 物を増やしたときに、描く三角形や描画の回数がどれだけ増えたかを確かめたいとき
  • 計測の結果をファイルに残して、あとで比べたり、ほかの人に見せたりしたいとき
  • 画面の更新に合わせた待ち（垂直同期）を外して、どこまで速く動くかを見たいとき

Profiler / 描画統計 (F4)

最初は画面の左下あたり（階層パネルの右）に、少し透けたウィンドウとして開きます。

上部

表示内容
計測する（オン）、Pause計測をするか、表示を止めるか。「OFF時はScope/Queryを発行しません」（計測を切ると、計測のための処理そのものを止めます）
垂直同期 (VSync)オンなら画面の更新周期に合わせて待ちます。オフにすると FPS の上限が無くなります（消費電力が増えることがあります）
Frame Budget ms1 フレームの目標の時間（既定 16.6 ms ＝ 60 FPS）。CPU や GPU の時間がこれを超えると赤く表示します。0 にすると赤くしません。GPU の時間が取れないフレームは判定しません
「FPS / UI dt」今の FPS と、前のフレームからの時間
「三角形 / 頂点 / 描画 回」描いた三角形・頂点の数と、描画の命令の回数
「カメラ内 三角形 / 頂点 / 描画 回」そのうちカメラに映る範囲に入っている量。下の「画面外を捨てれば全体の 数% まで落とせる見込み」は目安で、実際にはまだ捨てていません
「待ち除外の推定 FPS（CPU実仕事 / GPU待ち）」画面の更新待ちなどを除いたときの、FPS の目安
「CPU ms」「GPU ms」1 フレームにかかった時間。Frame Budget を超えると赤。GPU の時間が取れないときは「GPU --」

計測がうまくいかなかったフレームには、橙の注意（「GPU: disjoint frame…」「GPU Scope上限 数 に到達…」など）が出ます。そのフレームの数値の一部は使われていません。

Frame履歴

CPU ms と GPU ms の折れ線グラフと、最近のフレームの「min / avg / median / p95 / max」（最小、平均、中央値、遅い方から 5% の値、最大）が出ます。履歴はメモリーにだけ置き、300 フレームを超えると古いものから消えます（「履歴はRAMリングのみ（上限 300 frames）。ディスクへ常時追記しません」と出ます）。GPU の時間が取れなかったフレームは、統計からは除かれますが、グラフには 0 として描かれます。

Scope Tree / Hotspots

  • 表示 で「階層」「CPU重い順」「GPU重い順」を選びます。
  • 各行は「処理の名前、CPU の時間と親に対する割合、GPU の時間と割合、呼ばれた回数（x数）」です。
  • 行をクリックすると下に「Budget: 処理の名前」が出ます。CPU ms と GPU ms を入れて Budget適用 を押すと、その処理がその時間を超えたときに赤く表示されます。解除 で戻します。

出力 / ログ

欄働き
名前、計測ログを保存 (CSV + Trace)今までの履歴を Saved/Profile/ に、名前を付けた CSV（表計算ソフトで開ける）と Trace（時系列を見るツール用）で書き出します。書き出した場所が下に出ます
自動ログ（オフ）オンにすると、決まった間隔で自動で書き出します。ディスクへ書き続けるのではなく、間隔ごとにまとめて書きます。環境変数 REPLAY_AUTO_PROFILE が空でも 0 でもないときは、ここがオフでも自動ログがオンになり、間隔は 120 フレームになります
間隔(frames)（1800、60 以上）、最大世代（12）、自動ログ合計上限MiB（128）自動ログの間隔と、残す数・合計の大きさの上限。古い自動ログ（profile_ で始まるもの）から消します。手動で保存したログは消しません。ただし、手動で保存するときの名前を profile_ で始めると、自動ログと同じ扱いになり、消されることがあります

描画量 / State / Memory

見出し（閉じた状態）を開くと、描画の命令・三角形・インスタンスの数、エフェクトの処理の数、ゲーム内 UI の描画の数、GPU で動いたシェーダーの回数、Overdraw（1 ピクセルを平均何回塗ったか）、描画の状態を切り替えた回数、VRAM の使用量と上限、プロセスのメモリー、エンジンが持っているテクスチャ・バッファの大きさ、重複した GUID の数、シーンの GameObject とコンポーネントの数などが出ます。

最適化 (カリング / LOD / プリパス)

視錐台カリング（有効、除外した数）、自動LOD（有効、切替の画面高さ(px) 40〜1200、強制LOD：自動 / LOD0固定〜LOD3固定、LOD ごとの描画数）、深度プリパス（切り替えるとプロジェクト設定へ保存）の欄があります。

切り替えると描画の量が変わります視錐台カリング・自動LOD・深度プリパスは、今の DirectX 12 の描画でも使われます。カリングを切ると画面外の物も描くため、描画数が増えます。

DX12 Debug

Window > DX12 Debug で開きます（DirectX 12 で動いているときだけ表示されます）。どれも表示のみです。

見出し内容
Frameフレームの番号
Descriptor Heapsテクスチャなどを GPU に渡すための枠（CBV/SRV/UAV、Sampler）の使用数 / 上限、最大、断片化の割合、確保に失敗した回数
Upload / Fenceそのフレームで GPU へ送ったデータの量と上限、送信待ち・GPU の完了待ちの回数と時間
Caches / DXC読み込み済みのメッシュ・テクスチャ・描画設定（PSO）の数、PSO を使い回せた回数と作り直した回数、シェーダーのコンパイル回数・失敗回数・合計時間
GPU Passes描画の段階ごとの GPU の時間、描画の回数、インスタンス数、インデックス数、リソースの状態の遷移（barrier）の回数。描画パイプラインの状態の切り替え回数ではありません。時間が取れない段階は「--」。段階の名前は ShadowDirectional、ShadowLocal、GBuffer、Lighting、Forward、PostProcess、RuntimeUI、UIEffect、UIPreview、ImGui、Present、ModelEffect、ScreenEffect、Unknown です

使い方の例

重い原因を探す

  1. 重い場面を表示した状態で F4 を押し、Profiler を開きます。
  2. 「CPU ms」と「GPU ms」を見て、Frame Budget（16.6 ms）を超えて赤くなっているのがどちらか確かめます。
  3. Scope Tree / Hotspots の 表示 を、CPU が重ければ「CPU重い順」、GPU が重ければ「GPU重い順」にし、上に来た処理の名前を見ます。
  4. 物の数が原因に見えるときは、「三角形 / 描画 回」の数を、物を減らす前と後で比べます。

計測の結果を残して比べる

  1. 比べたい場面を表示し、しばらく動かして履歴をためます。
  2. 出力 / ログ の 名前 を「before」にして 計測ログを保存 (CSV + Trace) を押します。
  3. 直したあとに同じ場面で「after」として保存し、Saved/Profile/ の 2 つの CSV を表計算ソフトで比べます。

決まった条件で繰り返し測るときは、起動オプションの --profile-scene を使うと、エディターを操作せずに同じ手順で測れます（起動オプション）。
