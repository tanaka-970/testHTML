シェーダ一覧

対象：ブランチ sinotake / コミット 9eb9813

プロジェクトのシェーダー（.hlsl）を一覧にし、コンパイルに成功しているか、どんな値（プロパティ）を公開しているかを確かめるウィンドウです。Window > シェーダ一覧 で開きます。

こんなときに使う

  • 物が赤紫（マゼンタ）で表示される、見た目が変わらないなど、シェーダーがうまく動いていないときに、コンパイルのエラーを探したいとき
  • 自分で書いた、または Shader Composer で作ったシェーダーが、マテリアルで選べるように登録されているかを確かめたいとき
  • シェーダーの #pragma property に書いた値が、正しく読み取られているか（名前、範囲、既定値）を確かめたいとき
  • .hlsl を書き換えたあと、エディターを起動し直さずにコンパイルし直したいとき

上部

表示働き
再走査シェーダーのフォルダーを探し直して、一覧を作り直し、コンパイルします。#pragma を書き換えたときや、ファイルを足したときに押します。探すのは Shader/Materials、Shader/Layers、Shader/PostProcess の中（下のフォルダーも含む）の .hlsl です。replay_guid が無いファイルには GUID を付けて、ファイルに書き込みます（「GUID を採番しました: …」）。置いたフォルダーと replay_domain が違うときは、フォルダーの方を使って警告を出します。一覧を作り直すので、前回成功した結果は残りません
全部コンパイル探し直さずに、今の一覧のシェーダーをすべてコンパイルし直します。コンソールに「コンパイル成功 数 枚 / 失敗 数 枚」と出ます
保存で自動コンパイルオンの間は、1 秒ごとに .hlsl の保存を調べ、変わったシェーダーを自動でコンパイルし直します。一覧にまだ無い新しいファイルは拾わないので、足したときは 再走査 を押します
集計の行「シェーダ走査: 数 枚見つかり 数 枚を登録 / コンパイル成功 数 / コンパイル失敗 数 / GUID 採番 数 / 書式エラー 数 / GUID 重複 数 / 読み込み失敗 数」（0 の項目は出ません）

問題があると、次の文が色付きで出ます。

  • 「コンパイルに失敗したシェーダが 数 枚あります。下の赤い行をクリックすると該当行が開きます。」
  • 「GUID が重複しています。コピーしたシェーダの replay_guid を消してください。」（.hlsl をコピーして作ると、同じ GUID になります）
  • 「#pragma の書式エラーが 数 件あります。コンソールを見てください。」

シェーダーが 1 枚も見つからないときは、「シェーダが 1 枚も見つかりません。」と、置き場所の一覧（Shader/Materials（surface）、Shader/Layers（layer）、Shader/PostProcess（postprocess））が表示されます。

一覧

シェーダーごとに「分類/名前 [種類]」の見出しが並び、右に状態が色付きで出ます。見出しを閉じたままでも状態が分かります。

状態意味
OK（緑）使うすべての変種でコンパイルに成功しています
失敗（前回のを使用中）（橙）今回のコンパイルに失敗しましたが、前に成功した結果で表示を続けています。書き換えた内容はまだ反映されていません。再走査 のあとに失敗したときは前の結果が無いので、「失敗」になります
失敗（赤）一度もコンパイルに成功していません。このシェーダーを使うマテリアルは赤紫で表示されます

見出しを開いたとき

表示内容
ファイルの場所、「GUID …」シェーダーのファイルと、見分けるための GUID
Visual Studio で開く.hlsl を Visual Studio で開きます
このシェーダを再コンパイルこのシェーダーだけをコンパイルし直します
変種ごとの状態Static（動かないメッシュ用）、Skinned（骨で動くメッシュ用）など、使う変種ごとに「OK」か「失敗」。Static は通って Skinned だけ失敗することがあるので、分けて表示します
診断の行「(行番号) コード: 内容」。エラーは赤、警告は橙です。行をクリックすると、その .hlsl のその行が Visual Studio で開きます（エンジンが足した部分を除いた、元のファイルの行番号です）
「定数バッファ 数 バイト / テクスチャ 数 枚」公開している値が使う大きさ
プロパティの一覧「表示名 (名前 種類)」と、テクスチャなら「t番号 / 既定 white」、範囲なら「範囲 最小 〜 最大 既定 値」など。#pragma property が無いときは「#pragma property がありません。」
自動生成される cbuffer開くと、公開している値からエンジンが作る HLSL の宣言を表示します。コピー でクリップボードへ写せます

ここに並ぶプロパティが、そのままマテリアルのインスペクターの Shader Properties になります（マテリアルの編集）。

使い方の例

赤紫になった物の原因を探す

  1. 物のマテリアルを選び、インスペクターの Shader 欄で使っているシェーダーの名前を確かめます。「Missing Shader」なら、シェーダーのファイルが無くなっています。
  2. Window > シェーダ一覧 を開き、そのシェーダーの見出しの状態を見ます。
  3. 「失敗」なら見出しを開き、赤い診断の行をクリックして、Visual Studio でエラーの行を直します。
  4. 保存し、このシェーダを再コンパイル を押して「OK」になることを確かめます。

シェーダーに値を足して、マテリアルで変えられるようにする

  1. .hlsl に #pragma property の行を足して保存します。
  2. シェーダ一覧の 再走査 を押します。
  3. 見出しを開き、プロパティの一覧に足した値が出ていることを確かめます。
  4. そのシェーダーを使うマテリアルを選ぶと、インスペクターに新しい欄が出ます。
