イベント進行・UIフロー・シーン構成

対象：ブランチ sinotake_test / コミット aa27b6b3（コードから書いた内容。実機での確認はまだ）（2026-10-07 に入った機能を追記）

コードを書かずに、ゲームの進行（エリアに入ったら扉を開けて会話を始める、など）と、メニュー画面の切り替え、部屋ごとのシーンの読み込みを作る仕組みです。どれもノードをつないだ図をファイルに保存し、シーンに置いた部品が実行します。

こんなときに使う

  • プレイヤーがエリアに入ったら、扉を開け、少し待って、会話パネルを出したい（イベント進行）
  • タイトル・ゲーム・設定・ポーズの画面を、ボタンで行き来させたい（UIフロー）
  • 広いマップを部屋ごとのシーンに分け、近づいた部屋だけ読み込みたい（シーン構成）
  • よく使う GameObject のまとまりを、名前を付けてすぐ選び直したい（選択セット）

部品は コンポーネントを追加 > 進行・画面（選択セットは エディター）にあります。

イベント進行

  1. Window > イベント・進行エディタ を開き、新規 を押します。ひな形「エリア・扉・会話」（エリアに入る → 扉を開く → 扉を待つ → 会話パネルを表示 → 会話を開始）が入ります。
  2. ノードを選ぶと右側に項目が出ます。名前・待つ秒数・イベント名・変数名などを決め、次へ接続 でつなぎます。
  3. 保存 でファイルにします（保存して開く・別名保存 もあります）。
  4. フローをシーンへ配置 を押すと、シーンに Event / UI Flow の付いた GameObject ができます。ノードの 対象スロット と同じ番号に、動かす GameObject（扉・会話パネルなど）を割り当てます（階層の選択を割り当て でも割り当てられます）。
  5. エリアの判定には、Trigger の Collider を付けた GameObject に ワークフロートリガー を付け、シグナル名 をイベントのノードと同じ名前にします。
  6. その場で試す・1ノード進める で、実行しなくても流れを確かめられます。実行履歴（最新256件） に通ったノードが残ります。

「一度だけ実行」がオンのノードは、2 回目以降は飛ばします。「設定チェック」に、イベント名が空・移動先シーンが未指定などの問題が件数つきで出ます。

UIフロー

  1. Window > UIフローエディタ で 新規 を押します。ひな形「タイトル・設定・ポーズ」（タイトル・ゲーム・設定・ポーズの 4 画面と戻る）が入ります。
  2. 画面 ノード 1 つが 1 枚の画面（Canvas などの GameObject）です。最初の画面にする で始まりの画面を決めます。
  3. 画面どうしをつなぎ、接続ごとに ボタンのスロット（その画面のどのボタンで移るか）を決めます。前の画面へ ノードで、来た画面へ戻ります。
  4. ポーズ画面のように時間を止めたい画面は この画面ではゲーム時間を止める をオンにします。
  5. シーンへ配置し、画面とボタンの GameObject を対象スロットに割り当てます。

UIフローには「画面」と「前の画面へ」のノードだけが使えます。

シーン構成

  1. Window > シーン構成エディタ で 部屋を追加 を押し、部屋のシーン に読み込むシーンを選びます。位置・回転（度）・拡大率で置き場所を決めます。
  2. 部屋ごとに 常時読み込み か 範囲に入ると読み込み を選びます。範囲は 範囲の半幅（既定 10, 5, 10）で、出てから 解放までの余裕（既定 5 m）を過ぎると外します。境目で読み込みと解放を繰り返さないための余裕です。
  3. 部屋どうしを 部屋の接続 でつなぐと、Scene Composition の「接続した隣の部屋を先読み」で隣も読み込めます。
  4. 保存してシーンへ配置し、シーン構成の観測対象を設定 で、範囲の判定に使う物（プレイヤーなど）を決めます。
  5. 構成から編集用シーンを作成 で、全部の部屋を並べた編集用のシーンを作れます。

選択セット

Window > 選択セット のパネルで、いま選んでいる GameObject のまとまりに名前を付けて保存し、あとでまとめて選び直せます。セットはシーンの「選択セット」コンポーネントとして保存され、削除済みの対象はパネルから整理できます。
