Animator

対象：ブランチ sinotake / コミット 9eb9813（2026-10-24 に sinotake_test / 28995f39に合わせて追記・修正。追記分はコードから書いた内容）

骨の入ったモデルのアニメーションを再生するコンポーネントです。「待機」「走る」のような状態（State）ごとに再生するアニメーションを決め、条件がそろったら別の状態へ遷移（Transition）させます。姿勢は同じ GameObject の Skinned Mesh Renderer に表示されます。

UI やオブジェクトの位置・色などを時間で動かすときは、このコンポーネントではなく Motion Player を使います。

2026-10-22 追記状態には、GLB の中のアニメーション（クリップ番号）の代わりに、エンジンで作った RigClip（.replayrig、states[番号].rig_clip_path）を割り当てることもできます。作り方は モデルにアニメーションを追加する。

こんなときに使う

  • 骨の入ったキャラクターに、待機・歩く・走るなどのアニメーションを付けたいとき
  • 速さやボタンの入力に合わせて、アニメーションを自動で切り替えたいとき（Transition と条件）
  • スクリプトから、決まったアニメーションに切り替えたいとき

接地中・空中・速度の条件この 6 つは、同じ GameObject に付いた Character Motor（Gameplay 分類のテンプレート部品）の状態を見ます。Character Motor が無いか無効のときは、どれも成り立ちません。自分で作ったキャラクターでは、C# スクリプトから Bool や Float のパラメーターを設定して判定してください。

Bool・Float・Trigger の条件に使う名前は、どこかで登録しておく必要はありません。C# スクリプトから設定した名前がそのまま使われます。パラメーターは実行を始めるたびに空に戻ります。

動き方

  1. 実行を始めると、開始 State の状態に入ります。
  2. 毎フレーム、遷移を Transition 1 から順に 調べます。遷移元 が今の状態に合い、遷移先 の状態があって今の状態と違い、条件 が成り立つ遷移が見つかったら、その状態へ移ります。
  3. 1 フレームで移るのは 1 回だけです。複数の遷移が成り立つときは、番号の小さいものが勝ちます。
  4. 状態に入ると、再生位置は 0 に戻ります。ブレンド時間 が 0 より大きければ、その秒数をかけて前のアニメーションから混ぜながら切り替わります。
  5. 再生 がオンの間、再生位置は「経過時間 × 全体再生速度 × 状態再生速度」ずつ進みます。

状態が変わると、エンジンに AnimatorStateChanged というイベントが送られます。イベントには、前の状態の名前（previous_state）、新しい状態の名前（state）、前と新しいアニメーションの番号（previous_clip、clip）、ブレンド時間（blend_time）が入ります。

Animator を無効にすると、表示は続きますが、その時点の姿勢で止まります。

名前を指定してアニメーションを再生する

コンポーネントの画面で選ぶ

  1. Animator の モデルのアニメーション 一覧から GLB / glTF 内のアニメーション名を選びます。状態を登録する必要はありません。
  2. 選んだ名前は 再生アニメーション名 としてシーンに保存され、次にゲームを開始すると、その動きを使います。「再生」がオフなら停止した状態で準備されます。
  3. ゲーム実行中は 選んだアニメーションを再生、一時停止、再開、停止 で操作できます。再生ボタンは先頭から再生し直します。
  4. 登録した状態を使う場合は、ゲーム実行中の 状態名から再生 で選びます。開始時から状態設定を使うには、モデルの一覧で 状態設定を使う を選び、再生アニメーション名を空にします。

この操作はインスペクターの Animator 内と、アニメーション Workspace のゲーム連携設定にあります。開始アニメーション名を指定したときの直接再生では、状態グラフの自動遷移は適用しません。状態の再生を指示すると状態グラフへ戻ります。

C# から名前を指定する

// animator は取得済みの ReplayEngine.AnimatorComponent
animator.Play("Attack");                 // 状態名を優先。無ければモデル内の名前
animator.PlayState("Attack");            // 登録した状態名だけを対象にする
animator.PlayAnimation("Attack");        // GLB / glTF 内の名前だけを対象にする
animator.PlayAnimation("Run", 0.15f);    // 0.15 秒でブレンド
animator.PlayAnimation("Run", 0, 0.5f);  // 0.5 秒の位置から開始
animator.Pause();
animator.Resume();
animator.Stop();

名前は大文字・小文字も含めて一致させます。モデル内に同名のアニメーションが複数あると直接指定は失敗します。存在しない名前や不正な引数でも失敗を返し、その時点の再生状態を保ちます。状態名とモデル内の名前が同じなら、PlayState / PlayAnimation で対象を明示できます。C++ は同じ名前のメソッドが bool を返し、C# は RuntimeStatus を返します。

.replayrig は何に使うか

.replayrig は、エンジンで編集した骨のキーやポーズを保存するファイルです。モデルの形やテクスチャは含みません。次の用途があります。

  • 編集を再開する：アニメーション Workspace の「保存」で残し、後から「ファイル...」で読み込む。
  • モデル本体と別に動きを管理する：Idle.replayrig、Attack.replayrig のように分けて保存する。
  • GLB に書き込まず再生する：Animator の状態にある「RigClip パス」へ割り当て、その状態名を PlayState で再生する。
  • 同じ骨構成で使い回す：階層パス・骨構成が一致するモデルへ読み込む。異なる骨構成へ自動で動きを移す機能ではありません。

GLB 内のアニメーションなら名前を直接指定できます。.replayrig はファイルを状態へ割り当て、その状態名で呼び出します。ファイル名だけを PlayAnimation に渡しても読み込まれません。Blender などほかのツールでも動きを使いたい場合は、アニメーション Workspace の「書き出し...」から GLB へ書き込みます。

旧方式（State 数が 0 のとき）

State 数 が 0 のときは、状態と遷移を使わず、次の決まった動きをします。以前に作ったシーンのための動きです。

  • 同じ GameObject の Character Motor が空中にいれば 旧: ジャンプクリップ、地面で 旧: 移動とみなす速度 より速く動いていれば 旧: 移動クリップ、それ以外は 旧: 待機クリップ を再生します。
  • Character Motor が無ければ、常に 旧: 待機クリップ を再生します。
  • 繰り返すかどうかは 旧: ループ で決まります。遷移のブレンドはありません。

アニメーションの入ったモデルをプロジェクトパネルから置いたときは、この旧方式で 旧: 待機クリップ が 0 になっています。状態と遷移を使うときは State 数 を 1 以上にします。

使い方

速さで待機と走りを切り替える

  1. アニメーションの入ったモデルをシーンに置きます。Skinned Mesh Renderer と Animator が付きます。
  2. State 数 を 2 にします。
  3. State 1 の 状態名 を Idle、クリップ を待機アニメーションの番号にします。
  4. State 2 の 状態名 を Run、クリップ を走るアニメーションの番号にします。
  5. 開始 State に Idle を入れます。
  6. Transition 数 を 2 にします。
  7. Transition 1：遷移元 Idle、遷移先 Run、条件 Float >、パラメーター speed、しきい値 0.1。
  8. Transition 2：遷移元 Run、遷移先 Idle、条件 Float <=、パラメーター speed、しきい値 0.1。
  9. C# スクリプトで、キャラクターの速さを毎フレーム SetFloat("speed", 速さ) で渡します。
