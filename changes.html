新しい機能の評価

機能評価できることゲームで使うときの注意
XPBDホース物理・ホースリール◎太さのある管が伸び縮みし、壁に当たって曲がるC# の HosePhysics.paidOutLength で長さを変えられる。GrapplerClimb のワイヤーで実際に使われている。見た目と長さの部品で、キャラクターを吊る力は出さない（振り子の動きはスクリプト側）
ワイヤー物理・ヘア物理・衝突形状○ロープのたるみ、髪の揺れ見本シーンあり、自動検証 75 項目が成功。インスペクターだけで組める。剛体を引っぱらない・髪どうしは当たらない。C# の型は無い（ScriptBehaviour の汎用の入口で値は変えられる）
膨張（4 部品＋膨張プロファイル）○空気を送って膨らませ、圧力・漏れ・ダメージで破裂ScriptBehaviour 用の型と RequestLeakAt などの関数があり、自動検証 19 項目が成功。ただし破裂のイベントが無い（State == 5 を見張る）、空気接続の「接続中」が既定オフ、簡易方式は見た目だけ大きくなり当たり判定は変わらない、XPBD変形は CPU メッシュ（Sliceable / Convex Collider）が必要
Physics Joint○扉・振り子・引き出し・ばね固定・ヒンジ・スライダー・スプリングとも自動検証が成功。接続先を空にしたときの「接続先アンカー」はワールド座標で、既定 0,0,0 のままだと原点へ引っぱられる。PhysX が無い予備の計算方式では動かない
装備ソケット・装備アタッチ○武器を手のボーンや名前付きの場所に持たせるインスペクターだけで使える。回転の欄はラジアン（ほかの多くの欄は度）
射出アンカー×撃って刺さり、動く物に付いていく発射（Launch）を呼ぶ手段が C# にもインスペクターにも無い。今は「装着中」か「命中物へ固定」で置いておくことしかできない。グラップリングは Raycast を使うスクリプトで作る（GrapplerClimb の方式）。発射用の C# API が必要
XPBD有限要素Softbody△ゼリーのようにつぶれて戻る自動検証は成功。ただし閉じた凸に近いモデル専用で、Mesh Renderer に加えて Sliceable か Convex Collider が要る（CPU メッシュのため）。Rigidbody を押し返さない片方向。Primitive の Cube / Sphere には使えない
Orbit Camera○三人称で周りを回るカメラ、壁よけマウス・キー・ホイールで動く。ゲームパッドのスティックでは回らない（ScriptBehaviour から yaw / pitch を書く必要あり）。Follow Target と同じカメラに付けない
Effekseer Emitter△Effekseer のエフェクトを再生各自が Tools\SetupEffekseer.ps1 を実行してから x64 でビルドする必要がある。準備していないビルドでも、エラーにならずエフェクトが出ないだけなので気づきにくい。1 回再生の部品で、出し直しは GameObject の有効・無効で行う。C# の型は無い
Particle Emitter の GPU駆動○大量の粒を GPU で軽く出す画像を設定すると使われない（丸い粒だけ）
太陽光条、影の光源半径、体積雲・月、水面の泡・しぶき、局所光の間接反射◎見た目の向上値を変えるだけで使える。太陽光条は既定で強度 0（出ない）
Convex Collider の頂点の元・複合凸◎モデルから動く当たり判定を作る以前はコードからしか形を作れなかったのが、インスペクターで作れるようになった

C# スクリプトの変更

Unity と同じ書き方に大きくそろえました。Unity の経験がある人には書きやすくなりましたが、以前の書き方と結果が変わる所が 3 つあります。プロジェクトの Scripts/ を調べたところ、影響を受ける書き方は見つかりませんでした。

結果が変わる変更
  • Quaternion.Euler・Quaternion.AngleAxis の角度が ラジアン → 度。ラジアンは EulerRadians / AngleAxisRadians（説明）
  • MonoBehaviour の transform.Translate(v) が ワールドの軸 → 自分の軸（説明）
  • MonoBehaviour の transform.Rotate が、オイラー角の足し算から回転の掛け合わせに変わった（複数軸を同時に回したときの結果が変わる）
追加評価内容
Time.timeScale・Time.fixedDeltaTime への代入◎一時停止メニュー、スローモーションがスクリプトで作れる。WaitForSecondsRealtime、Time.unscaledDeltaTime で止めた間も UI を動かせる（説明）
Invoke・InvokeRepeating・CancelInvoke◎名前で後から呼ぶ（説明）
コルーチンの入れ子、CustomYieldInstruction、停止時の finally◎yield return StartCoroutine(…) で待てる
Physics の Unity 表記（Linecast、Check…、…NonAlloc、layerMask、QueryTriggerInteraction）◎当たった Collider そのものが分かるようになった（説明）
Rigidbody の Unity 表記（ForceMode、constraints、Sleep、AddRelativeForce など）○MoveRotation / Move は補間せずにその場へ移る（Unity のキネマティックのような滑らかな移動ではない）（説明）
Vector3 / Quaternion / Color の Unity 表記（小文字の名前、Project、Reflect、Angle、FromToRotation など）◎（説明）

エディターの変更

  • Camera を選ぶと、シーンビューに写る範囲（視野ガイド）が出るようになりました（説明）。
  • シーンビューのカメラの移動速度が、物に寄っても遅くならなくなりました。カメラ操作中もギズモが消えなくなりました（説明）。
  • Window に Effekseer エフェクト作成 / プレビュー、プロジェクトパネルの作成に 膨張プロファイル が増えました。
  • 見本シーンを作る起動オプション（--create-…-showcase）と、物理系の検証（--validate-strands など）が増えました（説明）。
  • シーンファイルの版が 14 になりました（説明）。

見えない所の変更

コミットの半分以上は、描画・物理・ECS・JobSystem の処理の分割と高速化（並列化、割り当ての削減、GPU 駆動描画の作業領域の再利用など）です。操作や設定は変わりません。重さの改善はプロファイラー（F4）の物理の計測で確かめられますが、このページの作成では計っていません。

ゲーム制作のために足りないもの

  1. 射出アンカーを撃つ C# API（Launch・Detach）。今のままでは部品として使えません。
  2. 新しい部品の C# の型（Orbit Camera、Physics Joint、Softbody、Effekseer Emitter、ホースリール など）。今は ScriptBehaviour の汎用の入口で、内部名の文字列を書く必要があります。
  3. 膨張の破裂イベント（風船の OnBalloonPopped のようなもの）。
  4. Orbit Camera のゲームパッド対応。
  5. Effekseer の準備漏れの警告。準備していないビルドで Effekseer Emitter を置いたときに、コンソールへ知らせる表示があると安全です。
  6. Grass（草）のコンポーネントは実装の途中で、まだ追加できません。
