呼ばれる順番（ライフサイクル）

対象：ブランチ sinotake / コミット 9eb9813

MonoBehaviour を継承したクラスに、決まった名前のメソッドを書くと、エンジンが決まったタイミングで呼び出します。このページでは、その名前と呼ばれる順番を説明します。

こんなときに使う

  • 最初に 1 回だけ準備する処理（Start）と、毎フレーム動かす処理（Update）を、どこに書けばよいか決めるとき
  • 何秒か待ってから続きを動かしたいとき（コルーチン）
  • ぶつかったとき、トリガーに入ったときに処理を起こしたいとき（OnCollisionEnter、OnTriggerEnter）
  • ほかのスクリプトより先に、または後に動かしたいとき（Execution Order）
  • Update が呼ばれない、Start が 2 回目に呼ばれない、といった理由を調べるとき

メソッドの一覧

override は書きません。private・protected・public のどれでも呼ばれます。

書き方呼ばれるとき
void Awake()最初に 1 回。GameObject が有効になるまで待ちます。コンポーネント自体が無効でも呼ばれます
void OnEnable()コンポーネントが有効になるたび
void Start()
IEnumerator Start()		初めて有効になったときに 1 回だけ。無効にしてからまた有効にしても、もう呼ばれません。IEnumerator で書くとコルーチンとして動きます
void Update()毎フレーム 1 回
void FixedUpdate()物理の 1 刻み（1/60 秒）ごと。1 フレームに 0 回のことも、複数回のこともあります
void LateUpdate()毎フレーム、全員の Update と物理が終わったあと
void OnDisable()コンポーネントが無効になるたび
void OnDestroy()コンポーネントが消えるとき
void OnCollisionEnter(Collision collision)
OnCollisionStay、OnCollisionExit		ぶつかり始めた・ぶつかっている間・離れたとき（下を参照）
void OnTriggerEnter(Collider other)
OnTriggerStay、OnTriggerExit		トリガーに入った・入っている間・出たとき
形が違うと呼ばれません名前が合っていても、引数や戻り値の形が表と違うと呼ばれません。そのときは Play を始めたときにコンソールへ「（クラス名）.Update は呼び出されません。見つかった形: …」という警告が出ます。

動くのは Play 中だけ

エディターで編集している間は、スクリプトのインスタンスは作られません。GameObject に付けただけでは Awake も Update も動きません。Play を押すと動き始め、止めると終わります（再生と停止）。

開始の順番

Play を始めたとき、シーンのすべてのスクリプトについて、次の順で進めます。1 つのスクリプトの Awake から Start まで一気に進めるのではなく、全員の Awake が終わってから全員の Start に進みます。

  1. 全員のインスタンスを作る
  2. 全員のフィールドに、インスペクターで設定した値を入れる
  3. 全員の Awake と OnEnable
  4. 全員の Start

そのため、Awake の中から、ほかのスクリプトのフィールドの値を読めます。途中で追加された GameObject やコンポーネントは、次のフレームの初めに同じ順で開始します。

1 フレームの順番

  1. 全員の Update
  2. 物理：たまった時間ぶん、「全員の FixedUpdate → 物理の計算」を繰り返す（最大 5 回）
  3. 全員の LateUpdate
  4. トリガーと衝突の判定、ほかのコンポーネントのイベントの配送
  5. スクリプトへ衝突・トリガーのメソッドを呼び、コルーチンを進める
  6. カメラの追従、音の更新

入力は Update で読み、力を加えるなど物理に関わる処理は FixedUpdate に書くと、この順番に合います。

スクリプトどうしの順番

各段階の中の順番は、ふつうはヒエラルキーの上から、同じ GameObject の中ではコンポーネントの上から順です。順番を決めたいときは、Script コンポーネントの Execution Order に整数を入れます。

  • 小さい数ほど先に呼ばれます。既定は 0 です。マイナスも使えます。
  • 同じ数どうしは、ヒエラルキーとコンポーネントの順です。
  • 並べ替わるのは Update・FixedUpdate・LateUpdate のそれぞれの中だけです。モーション、プロパティ接続、UI のレイアウトなど、そのあとに動く処理の順番は変わりません。

有効・無効にしたとき

操作呼ばれるものコルーチン
コンポーネントを無効にする（enabled = false）OnDisable。Update などは呼ばれなくなります止まらずに続きます
GameObject を非アクティブにする（親を非アクティブにした場合も同じ）OnDisable止まります。また有効にしても途中から再開はしません
もう一度有効にするOnEnable（Start は呼ばれません）

衝突とトリガー

衝突やトリガーの起き方は 物理（Rigidbody と Collider） を見てください。スクリプトでは、メソッドを書いたものだけに届きます。

Collision で分かること

名前内容
gameObject相手の GameObject。相手がもう消えているときは null
transform相手の Transform
collider当たった相手の Collider
relativeVelocityぶつかったときの相対速度
contactPoint接触した位置
contactNormal接触面の向き
penetrationDepthめり込んだ深さ

OnTriggerEnter などには、相手の Collider が渡されます。相手が分からないトリガーの通知は届きません。

コルーチン

何フレームかにわたって少しずつ進める処理は、IEnumerator を返すメソッドに書いて StartCoroutine で始めます。

IEnumerator Blink()
{
    for (int i = 0; i < 3; ++i)
    {
        Debug.Log("点灯");
        yield return new WaitForSeconds(0.5f);
    }
}

void Start()
{
    StartCoroutine(Blink());
}
書き方意味
StartCoroutine(処理)始めます。呼んだその場で最初の yield まで進みます。戻り値の Coroutine で止められます
StopCoroutine(coroutine)1 つ止めます
StopAllCoroutines()このスクリプトのものをすべて止めます
yield return null;次のフレームまで待ちます
yield return new WaitForSeconds(秒);指定した秒数だけ待ちます。時間の倍率（Time.timeScale）の影響を受けます
yield return new WaitUntil(() => 条件);条件が true になるまで待ちます
yield return new WaitWhile(() => 条件);条件が true の間、待ちます

2 回目以降の続きは、1 フレームの順番の 5 番目（LateUpdate と衝突の配送のあと）で進みます。

例外が起きたとき

  • 例外はエンジンが受け止め、コンソールに「[クラス名] Update で例外: メッセージ」と、GameObject 名、スタックトレースを出します。
  • Awake で例外が起きたスクリプトは、そのコンポーネントが無効になり、OnEnable や Start へ進みません。
  • それ以外のメソッドで例外が起きても、ほかのスクリプトは止まらず、次のフレームも同じメソッドが呼ばれます。

時間とログ

名前内容
Time.deltaTime前のフレームからの秒数。時間の倍率を掛けたあとの値です
Time.fixedDeltaTime物理の 1 刻みの秒数
Time.frameCountフレームの番号
Time.timeScale時間の倍率。スクリプトからは読むだけで、変えられません
Debug.Log(内容)、Debug.LogWarning、Debug.LogErrorコンソールに出します。2 つ目の引数に GameObject やコンポーネントを渡すと、どの GameObject のログかが付きます
Debug.LogException(例外)例外をエラーとして出します
Debug.Assert(条件, 内容)条件が false のときだけエラーを出します
Log、LogWarning、LogErrorMonoBehaviour の中で使える短い書き方。自分の GameObject が自動で付きます

使い方の例

3 秒後に自分を消す

using System.Collections;
using ReplayEngine;

namespace Game;

[ReplayGuid("（作ったときの値のまま）")]
public class AutoDestroy : MonoBehaviour
{
    public float seconds = 3.0f;

    IEnumerator Start()
    {
        yield return new WaitForSeconds(seconds);
        Object.Destroy(gameObject);
    }
}

弾やエフェクトに付けておくと、出てから決まった秒数で消えます。Start を IEnumerator で書くと、そのままコルーチンになります。

触れたアイテムを消す

void OnTriggerEnter(Collider other)
{
    Debug.Log(other.name + " が触れました");
    Object.Destroy(gameObject);
}

アイテムの GameObject に付け、アイテムの Collider の Trigger をオンにします。トリガーが起きる条件は 物理（Rigidbody と Collider） を見てください。

ほかのスクリプトより先に準備する

  1. 先に動かしたいスクリプトの Script コンポーネントを選びます。
  2. Execution Order を -10 などのマイナスにします。既定の 0 のスクリプトより先に、Update などが呼ばれます。
