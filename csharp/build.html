ビルドと、動かないとき

対象：ブランチ sinotake / コミット 9eb9813

C# スクリプトは、書いたあとにビルド（コンパイル）して、エディターに読み込ませると動くようになります。このページでは、ビルドのしかたと、スクリプトが動かないときに見る場所を説明します。

こんなときに使う

  • .cs を書き換えたのに、ゲームの動きが変わらないとき
  • 作ったスクリプトが、Add Component の一覧に出てこないとき
  • インスペクターの状態に Unresolved や Error と出ているとき
  • 別の PC でプロジェクトを開き、はじめてスクリプトを動かすとき

必要なもの

  • .NET 8 SDK。エディターは、環境変数 DOTNET_ROOT、C:\Program Files\dotnet、C:\Program Files (x86)\dotnet の順に探します。見つからないと「hostfxr.dll was not found. Install .NET 8 SDK/runtime.」と出ます。
  • コードの編集には Visual Studio を使います。スクリプトを作ると Visual Studio で開きます。

ビルドのボタン

プロジェクト ウィンドウの C# Scripts の欄にあります。

表示働き
C# をすべて更新（青いボタン）スクリプトの一覧を作り直し、ビルドして読み込みます。迷ったらこれを押します
自動更新（チェック）オンにすると、.cs を保存したときに自動でビルドします
Open Selected .csプロジェクトパネルで選んでいる .cs を Visual Studio で開きます
変更検出 → まもなく更新
変更検出済み（自動更新は無効）		.cs の変更を見つけたときに、ボタンの右に黄色で出ます
個別に実行 > Refresh C# Catalogスクリプトの一覧だけを作り直します。新しく作った .cs を Add Component に出したいときなど
個別に実行 > Build && Reload C#ビルドと読み込みだけを行います

欄の下には、スクリプトのプロジェクトファイル（Scripts/RePlayGameScripts.csproj）とソリューション（Scripts/RePlayScripts.sln）の場所が表示されます。

自動でビルドされるとき

  • 自動更新 がオンのとき：エディターは 1 秒ごとに .cs の保存を確かめます。保存を見つけた次の確認で、ほかに保存が続いていなければビルドします（Visual Studio が複数のファイルを続けて保存しても 1 回で済みます）。コンソールに「C# の変更を検出したので自動で再コンパイルします」と出ます。
  • Play を押したとき：ビルドしたものが無いか、.cs の方が新しいと、Play の前にビルドします。コンソールに「C# のソースが Assembly より新しいため、Play の前にビルドします」などと出ます。

ビルドに失敗したとき

  • コンパイルエラーはコンソールに、エラー番号、内容、ファイル、行とともに出ます。ファイルと行が付いたログは、選んで Visual Studio で開けます（コンソール）。
  • 「C# Compile/Reload 失敗。直前に成功した Assembly は維持しています。」と出て、前に成功したビルドのままで動き続けます。直したつもりの変更が反映されていないときは、まずこれを疑います。
  • 同じ内容のまま失敗していると、Play のたびに同じビルドを繰り返しません。.cs を直して保存するか、Build && Reload C# を押すと、もう一度ビルドします。

インスペクターの状態表示

Script コンポーネントの見出しは「（クラス名） (Script)」です。クラスが決まっていないときは「Script (未指定)」になります。その下に 状態 が出ます。

状態表示意味と対処
Runningインスタンス生成済み。Update が回っていますPlay 中で、動いています
Loaded型は解決済み。Play を押すとインスタンスが作られます正常です。編集中はこの状態です
Unresolved型が未解決。Build && Reload C# と Refresh C# Catalog を試してくださいビルドが済んでいないか、クラスの名前や ReplayGuid が変わってスクリプトが見つかりません
UnassignedScript が未指定ですどのスクリプトかが決まっていません。Add Component から付け直します
Error下の理由を確認してください赤い「理由」の欄に原因が出ます

その下に「インスタンス: あり / なし」が出ます。

Unresolved の間も、インスペクターで設定したフィールドの値は消えずに残り、スクリプトが見つかると元に戻ります。

動かないときに見る順番

  1. Play しているか：スクリプトは Play 中しか動きません。
  2. インスペクターの状態：Loaded や Running 以外なら、上の表の対処をします。
  3. コンソール：コンパイルエラー、例外、「… は呼び出されません」の警告が出ていないか。
  4. GameObject とコンポーネントが有効か：非アクティブの GameObject や、チェックを外したコンポーネントでは Update が呼ばれません。
  5. Saved/engine_log.txt：C# そのものが起動できていないときの原因が書かれます。「C# を用意できませんでした。C# の Component はすべて動きません」と出ていたら、.NET の場所やビルドを確かめます。

使い方の例

はじめて開いたプロジェクトでスクリプトを動かす

  1. .NET 8 SDK を入れておきます。
  2. エディターを起動し、プロジェクト ウィンドウの C# Scripts の欄で C# をすべて更新 を押します。
  3. コンソールに「===== C# 一括更新 終了 (Catalog=OK / Build=OK) =====」と出ることを確かめます。
  4. スクリプトの付いた GameObject を選び、インスペクターの状態が Loaded になっていることを確かめてから、Play を押します。

直したはずの変更が反映されない

  1. コンソールに「C# Compile/Reload 失敗。直前に成功した Assembly は維持しています。」が出ていないか見ます。出ていたら、前のビルドのまま動いています。
  2. その上に出ているコンパイルエラーを選び、Visual Studio で該当の行を開いて直し、保存します。
  3. 自動更新 がオフなら、個別に実行 > Build && Reload C# を押します。
  4. エラーが出なくなったら、もう一度 Play して確かめます。

作ったスクリプトが Add Component に出ない

  1. 個別に実行 > Refresh C# Catalog を押して、スクリプトの一覧を作り直します。
  2. それでも出ないときは、コンソールに一覧の更新の失敗（ReplayGuid やクラス名の重なりなど）が出ていないか見ます。
